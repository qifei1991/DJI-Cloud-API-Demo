# AI 开发资料目录约定

本仓库的**工程开发规范、领域知识、技能流程、架构说明**统一放在 `.ai/` 下，按类型分目录维护。

## 目录分工

| 位置 | 职责 |
| --- | --- |
| `.ai/rules/` | 编码、分层、数据库变更、CICD 等强制规范 |
| `.ai/knowledge/` | 领域知识（业务背景、字段含义、设备/文件结构、参数映射） |
| `.ai/skills/` | 可复用的改造流程与自测步骤 |
| `.ai/context/` | 架构概览与关键类索引 |
| `.ai/README.md` | 目录说明与维护约定 |
| `AGENTS.md`（仓库根） | 跨工具入口：项目定位、目录速览、最小必备约束与 `.ai/` 链接；不写正文，供 Codex/Cursor/Copilot 等只读根目录文档的工具使用 |
| `.qoder/` | **仅**保留 Qoder 工具自身的使用说明（自定义命令、工具规则）；需要工程规范时以引用方式指向 `.ai/`，不复制正文 |

## 要求

1. 对话中得出的关键技术点、版本兼容陷阱、设备端约定，必须落到 `.ai/` 对应文件中，不能只留在对话里。
2. 新增/修改规范时只改 `.ai/`；`.qoder/` 与根目录 `AGENTS.md` 里若需要，只写链接指向对应 `.ai/` 文档，避免两份内容漂移。
3. 涉及表结构的结论必须与 `sql/cloud_sample.sql` 同步；涉及报文/枚举的必须与 `cloud-sdk` 同步。
4. 未经用户明确要求，不执行 `git commit` / `git push`。
